# jinsil — Recovery 계약

> 오작동이 났을 때 어떻게 돌아오는지를 **실행 전에** 정한 계약. 사고 후 즉흥 대응 금지.
> 생성: 2026-09-23 (workspace-builder R24). 근거: 12-HOOK_AUTOMATION.md §0.4 Recovery-First.

## 기본 원칙

1. **복구 지점 우선** — 비가역 작업 전에는 반드시 복구 지점(커밋 또는 백업)을 만든다.
2. **같은 방식 재시도 금지** — 실패한 접근을 동일하게 반복하지 않는다. 원인 가설을 바꿔서만 재시도.
3. **모르면 멈춘다** — 복구 방법이 불확실하면 추가 변경 없이 사용자에게 보고한다.

## 실패 루프 (검증 실패 / 오작동 감지 시)

1. **멈춤** — 진행 중인 변경을 중단한다. 추가 쓰기 금지.
2. **상태 파악** — `git status` + 마지막 정상 상태(커밋/백업)를 확인한다.
3. **영향 범위 기록** — 무엇이 잘못됐고 어디까지 번졌는지 이 파일 하단 '사고 기록'에 1줄.
4. **되돌리기 또는 수습** — 아래 되돌리기 규칙에 따라 복구. 수습이 불확실하면 사용자 확인.
5. **재발 방지** — 원인을 `_meta/`에 case-study로 남기고, 반복 위험이면 가드 훅 패턴에 추가.

## 재시도 한계

- 같은 작업 실패 **3회** 도달 시 중단하고 사용자에게 보고한다 (가설·시도·결과 요약 포함).
- 외부 자원(API/시트/DB) 오류는 즉시 1회 재시도만, 그 후 보고.

## scope 잠금

- 복구 중에는 **원래 작업 범위 밖의 파일을 수정하지 않는다** — "고치는 김에"가 2차 사고의 주범.
- 복구가 범위 확장을 요구하면 사용자 승인 후 진행.

## 되돌리기 규칙

| 상황 | 복구 수단 |
|------|----------|
| 로컬 파일 오염 | `git checkout -- {파일}` (마지막 커밋으로) — 커밋이 없으면 복구 불가, 그래서 wrap 커밋이 복구 지점이다 |
| 잘못된 커밋 | `git revert` 우선 (이력 보존). reset --hard는 사용자 승인 필수 |
| 외부 정본(시트/DB) 오염 | 실행 전 백업본으로 복원. 백업이 없으면 즉시 사용자 보고 (자체 수습 금지) |
| 컨텍스트 손실 (컴팩션/세션 종료) | `_meta/` 기록 + 마지막 wrap 요약으로 재구성 |

## 비가역 외부 자원 (예방 가드 대상)

- `npm publish`
- `wrangler deploy`
- `wrangler secret put`
- `git push`

## 개발형 완료 검사

`python3 _meta/completion-check.py run -- 실제검사명령 인자...`로 프로젝트 테스트를 실행합니다.
정본 `_meta/completion-result.json`에는 실제 종료 코드와 검사 전후 입력 해시가 기록됩니다.
코드가 있는데 검증이 없거나 실패했거나 이후 코드가 바뀌면 Stop이 완료를 차단합니다.
스냅샷 v2는 src/tests/scripts/evals/prompts/config의 내용·파일 권한과 주요 루트 빌드·테스트 설정을 포함합니다.
pytest.ini·conftest.py·환경 파일(.env/.env.*)·프레임워크 설정 변경도 무효화합니다. 설정 값은 기록하지 않고 통합 해시에만 반영합니다.
보고서의 pass 문구는 대체 증거가 아닙니다. 검토자는 명령이 실제 요구사항 테스트인지 확인합니다.
이 기록은 명령 종료와 파일 스냅샷의 증거이며 테스트 적합성·전체 품질·암호학적 실행 증명을 뜻하지 않습니다.

## 추가 검증 스크립트 (선택)

기본 검사 `_meta/recovery-state.py`는 orchestration의 미완료 체크박스,
미처리 pending/classified 의도와 VERIFICATION.md의 마지막 `status: pass|fail|pending`
값을 읽는다. 코드 블록의 예시는 검사하지 않는다. Stop 훅이 미완료를 차단하고
SessionStart 훅은 git 초기화 여부와 무관하게 같은 상태를 주입한다.
작업을 마치면 체크박스와 검증 상태를 갱신하고 의도는 helper의 close로 닫는다.

사용자가 중단/취소를 요청하면 `_meta/recovery-state.json`에
`{"status":"paused","reason":"사용자가 요청한 이유"}` 또는 `cancelled`를 기록한다.
이것은 완료가 아니다. 미완료 목록은 보존하고, 재개 시 `active`로 바꾼다.
에이전트가 차단을 피하려고 임의로 paused/cancelled로 바꾸면 안 된다.
Stop의 stop_hook_active 루프 가드는 유지되므로 차단 1회 뒤에도 해결되지 않으면
완료를 선언하지 말고 실패/중단 상태와 남은 일을 보고한다.

`_meta/recovery-checks.sh`를 만들어두면 Stop 훅(stop-verify.sh)이 응답 종료 시마다 실행한다.
비-0 종료 = "끝났다고 말하면 안 되는 상태" → Claude의 정지가 차단되고 이 계약의 실패 루프가 주입된다.
워크스페이스의 "완료로 보지 않는 조건"을 결정론 스크립트로 옮겨 적는 곳이다.
